A security request arrives, and the team needs an answer it can rely on. It might involve a new threat report, a suspicious incident, or a decision about which security issues to fix first. Gathering the evidence and turning it into useful findings takes time.

Perception can carry out that work through playbooks that use one or more agents. The agents perform the analysis and organize the findings. You focus on requests that need your input and the evidence behind the conclusions the team plans to use.

## Turn a security request into checked findings

A threat report contains useful indicators and attacker behaviors, but the team needs more than an AI-generated summary. It needs findings that preserve the source evidence, distinguish uncertainty, and support the next investigation step. Extract threat intelligence organizes the report's details into findings for that review.

This module explains how to select a playbook, start and supervise a session, and review its findings before handing them over. The extraction procedure uses an approved Microsoft Defender Threat Intelligence (MDTI) article URL. The intended outcome is analysis and review, not deploying detections, blocking indicators, or changing the environment.

The agent's report still needs review. An important detail might be missing, or a conclusion might go beyond what the evidence supports. Before sharing the findings or acting on a recommendation, check what ran, what the agents found, and what still needs attention.

> [!NOTE]
> Perception is available in limited public preview to invited customers, and features and interface labels may change.

In this module, you learn how to:

- Identify the needed security outcome and choose an appropriate playbook.

- Confirm the required input and access, start a session, and follow its progress.
- Respond to agent requests and redirect or stop work when appropriate.
- Review the session findings against the available evidence and the original request.
- Record what can be used, what remains unresolved, and who acts next.

Required agents must already be configured. If access or configuration prevents the work, involve the Perception administrator.
