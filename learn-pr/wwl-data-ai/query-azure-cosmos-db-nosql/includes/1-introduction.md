A product catalog is mostly reads. A shopper filters a category by price, a landing page pulls the items tagged for a seasonal promotion, and a mobile client asks for the next 20 results. None of those requests knows an item identifier in advance, so none of them is a point read. They're all queries, and the cost of running the catalog is largely the sum of what those queries charge in request units (RUs).

Imagine you're a developer at Contoso building the product-catalog API. The catalog container holds a few hundred thousand product items, each one a JSON document with a nested array of tags. The API has to answer category and price filters without scanning the whole catalog, and reach inside the tags array without dragging every product across the network. It also has to return long result sets a page at a time, so a phone on a slow connection isn't waiting on a 40,000-item response. It also takes filter values straight from the query string, so a query assembled by string concatenation lets a caller's input be read as query syntax rather than as a value.

This module works through the query toolbox that solves those problems. You start with the query language itself: how a query reads JSON items, how it treats missing properties and mismatched types, and what the query engine charges you for. From there, you write parameterized queries with projections and built-in functions, and run them through the SDK. You then reach into nested arrays with correlated subqueries and expand those arrays with cross-product queries. You finish with continuation tokens, which let a stateless API resume a query where the previous request stopped.

By the end of this module, you can author parameterized Azure Cosmos DB for NoSQL queries that project the shape your application needs, query nested data with subqueries and cross-products, and page large result sets with continuation tokens.
