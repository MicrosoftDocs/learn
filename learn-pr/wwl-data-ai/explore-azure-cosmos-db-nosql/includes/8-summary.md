In this module, you learned to evaluate Azure Cosmos DB for NoSQL for an application and to stand up a first environment. The Contoso team's decision about a globally distributed application gives you a way to reason about the service that transfers to your own projects.

## What you learned

- Azure Cosmos DB for NoSQL is a fully managed NoSQL and vector database storing schema-agnostic JSON in a hierarchy of accounts, databases, containers, and items.
- Three ideas explain how it scales: request units as the currency of throughput, partitioning for horizontal scale, and global distribution for locality.
- You evaluate fit by weighing workload signals and AI use cases against the cases where a relational database or a different API is the better answer.
- You create an account with the Azure portal wizard, then use the Data Explorer to create a database and container, choose a partition key, and create, read, and query items.
