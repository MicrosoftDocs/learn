AI agents can use the permissions they're granted to perform requested actions. That means an organization's security strategy needs to account for more than what an agent can access. It also needs to account for what the agent is able to do with that access.

For example, an agent might be able to access customer records and update account information in a CRM system. If the agent has more access than it needs, sensitive customer data could be exposed. If the agent is directed incorrectly or behaves unexpectedly, it could modify records at scale, affecting business operations.

Before deploying an agent, organizations should consider questions such as:

- What information does the agent need to access?
- What actions can it perform?
- What could happen if it behaves unexpectedly?

These questions become increasingly important as organizations move from experimentation to agents operating across applications and workflows.

## Consider an agent in a customer service workflow

Imagine an organization deploying an agent to help resolve customer support requests. The agent can access customer information, look up order details, and take certain actions in business systems.

Several different problems could occur. The agent could:

- Access information beyond what it needs, increasing the risk of unauthorized exposure of sensitive business data. This highlights the need for identity controls.
- Make an incorrect or unauthorized change, affecting critical business processes, systems, or financial records. This highlights the need for management controls.
- Become unavailable, disrupting business operations that depend on the workflow it supports. This highlights the need for monitoring and management controls.
- Be targeted by attackers who use its permissions to access sensitive information or perform unauthorized actions, creating security, compliance, financial, and reputational risks. This highlights the need for containment controls.

Each situation has a different impact, but they all point to the same need: organizations need ways to establish appropriate boundaries around agent activity and maintain visibility into what agents are doing.

Agent governance therefore isn't simply a decision about whether an agent should be deployed. It's a way to define and enforce the controls that allow agents to operate within appropriate boundaries.
