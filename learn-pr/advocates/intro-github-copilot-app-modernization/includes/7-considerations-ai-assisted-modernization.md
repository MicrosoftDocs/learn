GitHub Copilot modernization can reduce modernization effort, but its output still needs technical and operational review. Apply these practices when changing critical software:

- **Review each stage.** Inspect assessment reports, strategy choices, plans, and changes. Use guided execution where available. For the general CLI plugin, don't assume automatic pauses or a new assessment for every request; use separate assessment, plan-creation, and execution commands when you need explicit stage boundaries.
- **Establish evidence with tests.** Generate missing characterization tests before upgrading, review their assertions, and run them on the original application. Confirm that the modernization workflow actually runs the required tests; some workflows make execution configurable. Add integration and end-to-end coverage for changed behavior. Passing tests don't prove complete equivalence.
- **Check support and compatibility.** Verify target runtimes, frameworks, SDKs, hosting platforms, and dependency versions against current documentation. Tool support for a version doesn't establish that your vendor still supports it or that every dependency is compatible.
- **Use suitable predefined tasks.** Start with an established task when its supported source and target match your scenario. Don't mistake an application-code task for provisioning, data transfer, or a complete production cutover.
- **Author custom skills deliberately.** Capture reviewed migration instructions and sanitized diff resources in a skill. Check the pattern's assumptions before reusing it in another application.
- **Review security beyond dependency CVEs.** Dependency scans are useful, but they don't establish correct authorization, secret handling, business logic, or secure deployment configuration. Review unresolved findings and risk decisions explicitly.
- **Use normal code review and release controls.** Keep changes in version control and your pull request process. Separate permission to generate code from permission to provision resources or deploy it.
- **Respect confidentiality constraints.** The product documentation states that modernization doesn't retain code snippets beyond the immediate session and doesn't collect, transmit, or store custom skills. Treat this as a statement about that process, not a blanket description of every Copilot service. Skills, plans, and upgrade state saved in your repository are still persistent artifacts. Follow your organization's rules for those files, telemetry, model usage, and cloud-agent access, and review the policies of the host or model provider you select.
- **Intervene when needed.** If the agent can't resolve a build failure or proposes an unsuitable transformation, stop and correct the plan or code. Resume only after the affected assumptions and results are understood.
