Azure Local networking connects physical switches and adapters, intent-managed host configuration, storage transports, Azure connectivity, and workload security. These layers cooperate, but they have different owners and different evidence of success. An adapter reporting **Up** does not establish storage performance. A successful connection to Transmission Control Protocol (TCP) port 443 does not establish an authenticated Azure transaction. A correctly written security rule does not help a workload unless it applies to that workload's actual path.

By the end of this module, you can:

- Understand Azure Local network configuration.
- Develop a nonoverlapping address plan that respects automatic storage configuration.
- Explain how Network ATC maps intent to host adapters and interfaces.
- Correlate intent state, SMB interface selection, RDMA activity, and application performance.
- Calculate whether a converged design can sustain its approved degraded-state demand.
- Distinguish direct egress, enterprise proxies, Azure Arc gateway, and supported private paths.
- Locate the correct software-defined networking owner for a denied workload flow.
- Select a supported network infrastructure design and explain which failures it can tolerate and what limits apply to expansion.
- Propose a narrowly scoped, reversible change when the supported procedure permits reversal.
